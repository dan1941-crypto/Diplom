# NIDS Traffic Analyzer — Handoff & Bootstrap Brief (`New Diploma`)

> **Назначение файла:** стартовый контекст для агента в изолированном проекте `New Diploma`.  
> **Ограничение:** вся работа ведётся **строго внутри папки `New Diploma`**. Исходные файлы в родительской директории (`S:\PythonProject`) не модифицируются и не используются напрямую (если проект открыт в изоляции с `File Access Policy = deny`).

---

## 1. Цель проекта

Создать с нуля современную, быструю и точную систему обнаружения сетевых вторжений (NIDS) с десктопным интерфейсом на **PySide6**, способную работать как в режиме **Live-захвата трафика**, так и при **анализе PCAP/PCAPNG-файлов**.

### Почему старая версия (`AI 3.12.py`, `backend.py`, `gui.py`) работала плохо
1. **Однонаправленный `flow_key`:** `(src_ip, dst_ip, src_port, dst_port, proto)` не нормализовался, из-за чего прямой и обратный трафик попадали в разные потоки, а все `Bwd`-признаки и `Down/Up Ratio` оставались нулевыми.
2. **Несовпадение единиц времени ($10^6$):** `Flow Duration` и `IAT` считались в секундах вместо микросекунд, как в CIC-IDS2017.
3. **~30 из 78 признаков всегда равны `0`:** `Fwd/Bwd Header Length`, `Init_Win_bytes_*`, `Active *`, `Idle *`, `Subflow *` и др. заполнялись нулями.
4. **Катастрофическое забывание при обучении:** `StandardScaler` обучался только на первом файле (`Friday-DDos`), а модель дообучалась последовательно файл за файлом без перемешивания.
5. **Узкое место по скорости и путям:** `pyshark` запускал `tshark` и парсил XML/PDML в Python; пути к файлам были захардкожены.

## 2. Целевая архитектура

### А. Единый слой захвата и извлечения признаков (Train = Inference)
- Отказ от `pyshark` и Java `CICFlowMeter.jar`.
- **Вариант 1 (основной):** `NFStream` (поверх `libpcap`/`Npcap`) — >80 двунаправленных потоковых признаков на C-скорости, нативная поддержка Live и PCAP/PCAPNG.
- **Вариант 2 (альтернативный для максимальной переносимости в `.exe`):** потоковый парсер на `dpkt` или `tshark -T fields` с нормализованным двунаправленным ключом `min((ip1, p1), (ip2, p2))` и единой шкалой времени.

### Б. Признаки и препроцессинг
- **Табличные потоковые фичи (~60–85):** двунаправленные счётчики, скорости (`bytes/s`, `pkts/s`), статистики длин пакетов и `IAT` (`min`, `max`, `mean`, `std`, квантили), TCP-флаги, `Init_Win_bytes`, `Header Length`, `TTL`.
  - IP-адреса и случайные `src_port` исключаются из входа; `dst_port` кодируется бакетами или embedding.
- **Последовательности первых пакетов (опционально для 1D-CNN / Transformer):** матрица `(signed_size, log_iat, tcp_flags)` для первых $N = 16\text{–}32$ пакетов потока.
- **Препроцессинг:** `np.log1p(clip(x, 0, max))` + `RobustScaler` или `QuantileTransformer`, обученный строго на всём перемешанном `X_train`.

### В. Обучение и метрики
- Единый перемешанный пайплайн по всем сценариям/дням датасета (без последовательного дообучения файл-за-файлом).
- Борьба с дисбалансом: **Focal Loss** или `class_weight` + oversampling редких атак.
- Целевые метрики: **Macro-F1**, **PR-AUC**, **False Positive Rate (FPR)**.

### Г. Модель и продакшн-инференс
- **Вариант А:** **Tabular ResNet** (`Linear -> LayerNorm/BatchNorm -> SiLU -> Dropout -> Residual Skip`, 3–4 блока шириной 256–512) + калибровка вероятностей (`Normal` / `Suspicious` / `Attack`).
- **Вариант Б:** **Dual-Branch** (`1D-CNN` / лёгкий `Transformer` по первым 16–32 пакетам + `Tabular ResNet` по статистике потока).
- **Инференс:** экспорт в **ONNX** (`onnxruntime`) для быстрого старта и упаковки в `.exe`.

### Д. Real-time пайплайн и PySide6 GUI
- Многопоточность: `Capture Worker` (Npcap / PCAP → завершённые потоки по `FIN/RST` или таймауту 15–30 с) → `Inference Worker` (батчи через препроцессор + ONNX) → UI.
- Функционал UI: переключатель **Live / PCAP**, верхние KPI-карточки, живой график трафика и угроз (`PyQtGraph` / `QtCharts`), таблица событий с severity и `confidence`, панель инспекции потока (топ-признаки), экспорт в CSV/JSON/PCAP.

## 3. Рекомендуемые датасеты (2022–2026)

- **Сетевые атаки / DDoS:** NetFlow v3 Benchmark Suite (`NF-UNSW-NB15-v3`, `NF-CSE-CIC-IDS2018-v3`), Gotham Testbed (2025), BCCC-cPacket-Cloud-DDoS-2024, CICIoT2023 / CICIoMT2024.
- **Шифрованный трафик / TLS / QUIC / малварь:** Annotated Encrypted Network Traffic Dataset (Zenodo 18336960), CESNET-TLS22 / QUIC22, BCCC-DarkNet-2025, VisQUIC.
